# Развёртывание стенда

Шаги описывают повторную сборку. После каждого этапа записывайте наблюдение и переходите дальше, когда выполнен критерий проверки. Схема и версии приведены [отдельно](architecture.md).

## 1. Подготовить хост и установочные пакеты

**Зачем.** Аппаратная виртуализация позволяет VirtualBox запускать 64-разрядные гостевые системы. Дистрибутивы и лицензии нужны отдельно для ОС и для защиты рабочей станции.

**Действие.** Включить SVM (AMD-V) либо VT-x (Intel) в UEFI. Установить VirtualBox 7.2.x. Получить Windows Server 2022 Evaluation и законно доступный установочный образ Windows 10 Enterprise 22H2. Скачать KSC 15.1.0.28509, отдельный пакет Агента 17.0.0.3992, KES 12.12 x64 и плагин управления. Для KES определить, доступна ли локальная пробная или иная учебная лицензия с нужными компонентами. Сверить подписи установщиков и SHA-256 по данным издателя, где доступны.

**Проверка и запись.** В Windows `VirtualizationFirmwareEnabled=True` либо «Виртуализация: включено» в диспетчере задач. Записать результат `VBoxManage --version` и статус доступности лицензии без кода активации.

[Oracle VirtualBox](https://www.virtualbox.org/wiki/Downloads) · [Windows Server Evaluation](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server-2022) · [Бюллетень и пакеты KSC](https://support.kaspersky.com/16351) · [Пробная версия Kaspersky для локального управления](https://www.kaspersky.ru/small-to-medium-business-security/downloads/endpoint-free-trial)

## 2. Собрать две ВМ и закрытую сеть

**Зачем.** Внутренняя сеть VirtualBox соединяет учебные ВМ между собой. Файлы, настройки и устройства физического хоста остаются вне обычного доступа гостевых ОС.

**Действие.** Создать KSC-SRV и KES-CLT по [схеме](architecture.md) и задать эти имена компьютеров в гостевых ОС. В VirtualBox задать Adapter 1 → Internal Network → `ksc-lab` на обеих ВМ. В гостевых ОС назначить адреса и маску из схемы. Оставить общие папки и буфер обмена выключенными. Для переноса доверенных установщиков использовать временный ISO в режиме чтения либо загрузку через временный NAT. Установить доступные обновления ОС и сделать снимки чистых ВМ. На KES-CLT создать две обычные локальные учебные учётные записи для матрицы USB.

**Проверка и запись.** Обе ОС загружаются. В каждой записать редакцию и сборку из `winver`, на внутреннем адаптере сверить IP по `ipconfig`. Проверку доступности порта выполнить после запуска KSC.

## 3. Развернуть KSC и подключить Агент

**Зачем.** СУБД хранит события и настройки. Агент на клиенте поддерживает связь с сервером.

**Действие.** На KSC-SRV установить SQL Server 2022 Express с экземпляром `SQLEXPRESS`. В установщике KSC выбрать установку Сервера администрирования и MMC-консоли, указать локальный экземпляр `KSC-SRV\SQLEXPRESS` и настроить учётные записи SQL по справке Kaspersky. Для подключения Агента задать адрес сервера `192.168.77.10` и оставить TLS на TCP 13000. Проверить, что правила брандмауэра для связи агента ограничены учебной сетью. В MMC установить плагин KES 12.12. Создать в KSC пакет Агента 17.0.0.3992 и автономный установочный пакет с заданным адресом, затем запустить его на KES-CLT. Переместить появившийся клиент в группу `Lab-Workstations`.

**Проверка и запись.** На клиенте проверить `Test-NetConnection 192.168.77.10 -Port 13000`, затем запустить `klnagchk.exe` из каталога Агента. В консоли открыть свойства KES-CLT и сверить версию Агента и отметку последней связи.

[Справка по установке KSC и учётным записям СУБД](https://support.kaspersky.com/ksc/15.1) · [Утилита klnagchk](https://support.kaspersky.com/ksc/15.1/3912)

## 4. Удалённо установить и активировать KES

**Зачем.** Задача KSC выполняет действие на устройстве, например устанавливает программу. Политика задаёт правила её работы.

**Действие.** Создать пакет KES из официального дистрибутива. Включить файловую защиту, «Контроль устройств» и «Контроль программ». Создать задачу удалённой установки, выбрать KES-CLT и доставку **через Агент администрирования**. После установки активировать KES действующей лицензией и обновить базы. Проверить, что используемая лицензия включает нужные компоненты.

**Проверка и запись.** В KSC сохранить итог задачи. На KES-CLT проверить версию установленного KES, активность компонентов и время последнего обновления. Состояние лицензии можно проверить командой `avp.com LICENSE /CHECK` из каталога KES. В журнал заносится только итог проверки без идентификаторов лицензии.

[Создание пакета KES](https://support.kaspersky.com/kes-for-windows/12.12/177937) · [Задача удалённой установки](https://support.kaspersky.com/kes-for-windows/12.12/177980) · [Компоненты по типу лицензии](https://support.kaspersky.com/kes-for-windows/12.12/176377)

## 5. Проверить детектирование и доставку события

**Зачем.** Проверка по требованию показывает, распознаёт ли KES стандартный тестовый объект. Список событий KSC помогает подтвердить, что результат дошёл до сервера.

**Действие.** На активированном KES-CLT подготовить тестовый файл по инструкции EICAR. Открыть проверку файла в KES или запустить `avp.com SCAN` для этого файла из каталога продукта. Сохранить отчёт проверки, затем синхронизировать Агент с сервером.

**Проверка и запись.** Сопоставить время, имя объекта, результат проверки и событие на сервере. Отдельно отметить реакцию при записи или чтении файла, если проводилась такая проверка. Записать наблюдения в [матрицу](verification.md).

[Инструкция EICAR](https://www.eicar.org/download-anti-malware-testfile/) · [Команда SCAN](https://support.kaspersky.com/kes-for-windows/12.12/181236)
