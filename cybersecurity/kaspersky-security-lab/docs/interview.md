# Демонстрация и собеседование

## Демонстрация за минуту

1. **Стенд.** Откройте [схему](architecture.md). На серверной ВМ работают KSC и SQL Server Express. На клиенте Агент получает задания и отправляет события, а KES выполняет проверки.
2. **Удалённая установка.** Откройте [строку INST-01](verification.md#проверки-повторной-сборки). В KSC зафиксирован один успешный результат. На клиенте установлена та же версия KES, что указана в пакете.
3. **Обнаружение EICAR.** Откройте [скриншот отчёта](../evidence/av-02-kes-local-report.png). В нём видно обнаружение и удаление одного тестового файла. После синхронизации Агент передал событие в KSC.
4. **Восстановление связи.** Покажите [результат LINK-02](../evidence/README.md#связь-агента-с-ksc). После отключения виртуального кабеля порт стал недоступен. После подключения связь и синхронизация восстановились.

## Рассказ о проекте

> На учебном стенде я подключал Windows 10 к Kaspersky Security Center через Агент администрирования, удалённо устанавливал KES и настраивал политики. В прежней практике работал с исключениями для USB и блокировкой запуска приложений. При повторной сборке подтвердили удалённую установку KES, восстановление связи после отключения виртуального кабеля и обнаружение EICAR при проверке по требованию. Результаты можно проверить по задаче установки, версии программы на клиенте и событиям в KSC.

## Вопросы для самопроверки

1. **Чем отличаются KSC, Агент и KES?** KSC управляет устройствами и собирает события. Агент обменивается данными с сервером. KES применяет правила на рабочей станции.
2. **Чем задача отличается от политики?** Задача выполняет действие, например установку или проверку. Политика задаёт параметры работы программы.
3. **Как подтвердить удалённую установку?** Сопоставить результат задачи в KSC с версией программы на клиенте.
4. **Почему открытого TCP-порта мало для диагностики?** Проверка порта подтверждает сетевую доступность. Для подтверждения защищённого подключения и обмена данными нужны вывод `klnagchk` и успешная синхронизация.
5. **Что показал EICAR?** Проверка по требованию обнаружила и удалила стандартный тестовый файл. Отдельный прогон при записи и чтении дал другой результат. Каждая проверка описывает конкретный способ запуска защиты.
6. **Как проверить точечное USB-исключение?** Использовать два носителя и две учётные записи. Проверить все сочетания, чтобы доступ сохранился только у разрешённого пользователя с разрешённым носителем.
7. **Как подтвердить блокировку приложения?** Сравнить исходный запуск, событие правила и запуск контрольной программы вне категории запрета.
8. **Что ограничивает стенд?** Проверки проведены на одной рабочей станции без домена. Статус поддержки виртуальной платформы и версии Windows указан в [ограничениях стенда](architecture.md#сеть-и-ограничения).
